## 二、翻译怎么做

### 1. 打开翻译文件

```
translation\ui_strings.tsv     UI 文本   1011 条
translation\subtitles.tsv      关卡字幕   918 条
```

UTF-8 编码的 TSV，制表符分隔，**没有任何引号转义**——因为原文里既不含制表符也不含真换行，
每一行就是一条完整记录。用 VS Code、Notepad++、或任何支持 UTF-8 的编辑器直接改就行。

六列：

| 列 | 说明 |
|---|---|
| `file` `key` | 定位用，**别动**，改了回填不上 |
| `context` | 字幕对应的语音文件名，UI 条目为空 |
| `tokens` | 该条必须保留的记号，以及首尾空格提示 |
| `en` | 英文原文 |
| `zh` | **译文填这里**（最后一列） |

留空 = 保持英文，可以分批翻，不用一次填完。

> **唯一的禁忌：译文里不能有制表符。** 粘贴时留意一下。
> 真混进去了构建时会报错并指出行号，不会静默出错。

### 2. 三类必须注意的东西

**记号必须原样保留。** 「必须保留的记号」列已经把每条用到的列出来了：

| 记号 | 含义 | 丢了会怎样 |
|---|---|---|
| `$USE$` `$FIRE$` `$JUMP$` | 运行时替换成玩家实际按键 | 显示成字面量 `$USE$` |
| `%s` `%d` | 格式化占位符 | 可能读取越界 |
| `\n` | 换行（反斜杠 + 字母 n，不是真换行） | 排版乱 |
| `\v183` | 特殊字符转义 | 显示异常 |

**首尾空格是有意义的。** 有 **55 条**原文首尾带空格，表里标了「首部空格」「末尾空格」。
比如 `"Viewing from "` 末尾那个空格后面要拼接玩家名字，吃掉就会粘在一起。
导入时会自动比对，不一致会告警。

> 这个坑我自己踩过：第一版导入脚本用了 `.strip()`，把这个空格吃了。现在不 strip 了。

**长度要收着写。** 菜单按钮、HUD 提示有版面限制。中文通常比英文短，风险不大，
但武器名、按键绑定名、计分板列标题、多人模式名要注意。

### 3. 生成汉化包

TSV 就是流水线格式，没有导入转换这一步——你改的文件构建脚本直接读。
改完 `translation\*.tsv` 后跑构建，它会回填译文、扫出字符集、生成字体子集、打包，
并装进 `client_mods`。过程中校验记号缺失和首尾空格异常，有问题会打印出来（告警不中断构建）。

**改完重启游戏就能看效果**，不用重新编译 DLL。

```bat
python tools\build_all.py --install
```

> **注意：这条命令目前跑不了在这台 Windows 上。**
> `build_font.py` 依赖 `fontTools` 和思源黑体（`/usr/share/fonts/opentype/noto/NotoSansCJK-*.ttc`），
> 这两样都在助手侧的 Linux 环境里，Windows 上没有。硬跑的结果是字体生成被静默跳过，
> 打出一个**不含字体的 vpp**，游戏里中文会整片消失——比报错更难查。
>
> 所以现在的流程是：**你改 TSV，然后说一声，由我这边执行构建并安装。**
> 如果想变成自助，有两条路：
> 1. 在 Windows 装 Python + `pip install fonttools`，并把 `build_font.py` 里的
>    `SOURCES` 改成本机字体路径；
> 2. 给 `build_all.py` 加一个「复用上次生成的字体」开关——只改文字、没有引入新汉字时，
>    字体本来就不需要重新生成，那样只依赖 Python 标准库。

### 3.1 Alpine 自有界面文字是另一套

`patches\alpine_ui.tsv`（100 条）是 Alpine Faction 自己的设置界面、按键名等，
**它不进 vpp，是编译进 DLL 的**。

| 改了哪个 | 要做什么 |
|---|---|
| `translation\ui_strings.tsv`、`translation\subtitles.tsv` | 重新构建 vpp，重启游戏 |
| `patches\alpine_ui.tsv` | **重打补丁 + 重新编译 DLL** |

第二种的完整流程：

```bat
python rf_cn\patches\apply_patch.py <ALPINE_SRC> --no-veh --revert
python rf_cn\patches\apply_patch.py <ALPINE_SRC> --no-veh
cd /d <ALPINE_SRC>\build
cmake --build . -j
copy /y bin\AlpineFaction.dll "<ALPINE_DIR>\"
```

**必须先 `--revert` 再重打**，否则源码树里留着旧译文、新定义匹配不上，会直接失败。

还要注意：`alpine_ui.tsv` 里新增的汉字**同样要进字体**。`build_all.py` 会扫这个文件，
所以改完它之后 vpp 也要重新构建一次，否则新字在界面上会凭空消失。

### 4. 字符集是自动的

`build_all.py` 会先扫一遍译文用到哪些汉字，再据此生成字体子集。
**译文里出现的字一定在字体里，没出现的一个不多收。**
所以随着翻译推进，字体会自然长大，你什么都不用管。

## 五、踩过的坑（避免重复）

| 坑 | 症状 | 原因 |
|---|---|---|
| 字体加载失败 | `FT_New_Memory_Face failed: 2` | Alpine 的 FreeType 没编 CFF 驱动，只认 glyf 轮廓 |
| 转换后仍失败 | 同上 | 文件头 `sfntVersion` 还是 `'OTTO'`，得改成 `0x00010000` |
| 补丁全部匹配失败 | old×0 | Windows checkout 是 CRLF，补丁字符串是 LF |
| 着色器编译失败 | `X3501: 'main': entrypoint not found` | 路径含中文，系统代码页 CP932 搅碎了路径 |
| 中文字太小 | —— | 官方字体是扁宽体，思源宽度只有 61%，用 upem 缩放补 |
| 源码注释乱码风险 | —— | 注入源码的内容必须纯 ASCII，GBK 尾字节可能是 `\` 吞掉下一行 |
